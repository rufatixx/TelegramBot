# EsimBot

ASP.NET Core 8 Web API с Telegram-ботом для продажи eSIM через API eSIM Access.
Обычная публикация для IIS или запуска через `dotnet EsimBot.dll`, без Docker.

## Структура

```text
BLL/
  DTO/               данные для сервисов, настройки и результаты операций
  Services/          каталог, цены, покупки, Telegram и выдача eSIM; каждый сервис со своим I-интерфейсом
DAL/
  DAO/               модели строк MySQL
  Repos/             отдельные Orders/Payments/Esims/AppStateRepository и одноимённые интерфейсы
  schema.sql         четыре таблицы
View/
  ApiControllers/    только вызов интерфейса BLL-сервиса и возврат HTTP-результата
Program.cs           регистрация зависимостей и запуск Web API
appsettings.json     заполненные рабочие настройки, исключены из Git; входят в Build и Publish
appsettings.Example.json  чистый шаблон без доступов; не входит в Build/Publish
appsettings.Local.json  сохранённая приватная резервная копия старого конфига, больше не загружается
```

## Запуск подготовленной установки

В **`appsettings.json` уже заполнены все необходимые доступы**: БД, ключ
шифрования, бот, eSIM Access и ID администратора. Дописывать технические настройки,
курс Stars, адрес webhook или ссылки на отдельный сайт не требуется.

1. Пополните баланс в кабинете eSIM Access: eSIM оплачивается поставщику до её выдачи.
2. Откройте `@RoamiSIMBot` своим администраторским аккаунтом и нажмите **Start**,
   чтобы бот мог присылать вам обращения и сообщения об ошибках.
3. Опубликуйте **EsimBot** обычной командой Publish или через профиль **Server**, перенесите всю папку публикации на сервер и
   запустите приложение. Серверу нужен доступ к Telegram, eSIM Access и частной БД.

Автоматически используются Polling без домена/webhook, определение языка Telegram,
встроенные условия на az/ru/en и поддержка через этого же бота. Тестовая оплата
выключена. Продажи разрешены конфигурацией, но каждый платёж проходит проверку
цены, состояния заказа и баланса поставщика **до списания Stars**. Это не резервирует
баланс между одновременными заказами: держите запас средств для закупок.

### Интерфейс как мобильное приложение

Главное меню, выбор страны, тарифы, заказы, инструкция и условия работают как один
экран внутри Telegram: кнопки редактируют текущее сообщение вместо создания новой
ленты. Позиция экрана хранится ключом `ui:screen:<userId>` в существующей
`app_state`; новая таблица не нужна. Если пользователь удалил экран, бот создаёт
его заново и запоминает новую позицию. Команды и поисковый текст после обработки
удаляются из приватного чата по возможности Telegram.

Счёт Telegram Stars, подтверждение оплаты/возврата, QR и инструкция установки тоже
входят в текущий экран: при следующем действии они удаляются. Заказ, чек и eSIM
сохраняются в БД и повторно открываются через «Мои eSIM». Отдельно остаются только
нерешённые обращения и критические уведомления администратора; после ответа
закрытое обращение удаляется автоматически. Кнопка поддержки включает Force Reply
и не ломает одноэкранный интерфейс. Флаги формируются из двухбуквенного ISO-кода перед
локализованным названием страны; для регионального/неизвестного кода используется
`🌐`, если из кода нельзя безопасно построить флаг.

На главном меню настроенного администратора дополнительно появляется кнопка
**«📊 Статистика»** и личная команда `/stats`. Обычным пользователям они не
показываются, а BLL-сервис отдельно проверяет admin ID. Экран без дополнительных
таблиц считает по нормализованным данным: пользователей, покупателей, заказы и их
состояния, успешные оплаты, возвраты, Stars до/после возвратов, выданные eSIM,
оперативный статус бота и текущий баланс поставщика. Кнопка обновления перечитывает
данные из БД и API поставщика; недоступность баланса не скрывает остальную статистику.

Три флага в макете телефона на лендинге — локальные SVG в официальных пропорциях:
Турция и Грузия 2:3, Азербайджан 1:2. Они не рисуются символами или генеративной
графикой и не зависят от внешнего CDN.

### Что остаётся в коротком конфиге

Все поля ниже уже заполнены локально. Менять нужно только при смене доступов или
желаемой наценки. Используется один `appsettings.json`; переменные окружения и
параметры запуска могут переопределить его. После изменения перезапустите приложение.
`appsettings.Local.json` не загружается даже если остался на старом сервере.

| Параметр | Назначение |
| --- | --- |
| `ConnectionStrings:EsimBot` | Отдельный пользователь MySQL `esim_bot_app`, не root. |
| `Storage:EncryptionKey` | Сохранить без изменения и резервировать отдельно от БД: иначе старые QR нельзя расшифровать. |
| `TelegramBot:Token`, `TelegramBot:AdminUserId` | Токен бота и ID администратора. |
| `Provider:AccessCode`, `Provider:SecretKey` | Доступ к eSIM Access с HMAC-подписью. |
| `Sales:MarkupPercent` | Наценка `10%` от закупочной цены. |
| `Sales:MinimumProfitUsd` | Минимальная расчётная добавка `$0.25` на заказ вместо процента, если он меньше. |

Для нового развёртывания с другими учётными записями заполняются только доступы.
В текущей установке БД и ключ шифрования уже созданы — создавать заново не нужно.

### Необязательные переопределения

Их **не нужно добавлять для запуска**:

- `Sales:Enabled=false` — вручную приостановить новые продажи; обработка уже
  полученных платежей и возвратов продолжится.
- `Sales:NetUsdPerStar` — заменить расчётную базу `$0.0117` на свою оценку поступлений
  за Star, до отдельной комиссии за topics. Подробности расчёта ниже.
- `Sales:SupportUrl` — дополнительная HTTPS-ссылка на поддержку; встроенная переписка
  остаётся доступна. `Sales:TermsUrl` вместе с собственной `Sales:TermsVersion` — свои
  условия вместо встроенных. Некорректные ссылки блокируют новые продажи.
- `TelegramBot:DefaultLanguage` — запасной язык `en` (также `az`/`ru`).
- `TelegramBot:Mode=Webhook` требует `WebhookUrl=https://домен/api/telegram/webhook`
  и случайный `WebhookSecret` из букв, цифр, `_` и `-`, рекомендуется 32+ символа.
- Для опубликованного Web API используйте именно `Webhook`. Режим `Polling` требует
  постоянно работающего процесса и перестаёт отвечать, если IIS/хостинг усыпляет сайт.
  Webhook-запрос Telegram автоматически будит веб-приложение; при холодном старте
  сервер отвечает `503`, и Telegram безопасно повторяет доставку обновления.
  По умолчанию Polling: никакие из этих полей не нужны.

Встроенные условия описывают работу приложения; они не заменяют проверку применимых
к вашему бизнесу требований к продавцу и обработке персональных данных.

### Безопасная проверка оплаты без покупки eSIM

У приложения есть отдельный режим **Telegram Test Environment**, управляемый
`PaymentTesting:Enabled`. Это реальный протокол оплаты тестовыми Stars, но **не
покупка и не имитация выдачи eSIM**. Каталог и все HTTP-запросы eSIM Access в этом
режиме заблокированы, даже если боевой `Provider:AccessCode` заполнен.

| Параметр | Значение для проверки |
| --- | --- |
| `PaymentTesting:Enabled` | `true` для теста; `false` для боевого режима. После изменения перезапустить приложение. |
| `PaymentTesting:BotToken` | Токен отдельного бота, созданного в тестовой среде Telegram. Боевой токен не подставляется автоматически. |
| `PaymentTesting:AdminUserId` | ID вашего **тестового** аккаунта. Сначала можно оставить `0`, запустить бот и отправить `/id`; затем заполнить ID и перезапустить. |
| `PaymentTesting:InvoiceStars` | От `1` до `100` тестовых Stars, по умолчанию `1`. |
| `ConnectionStrings:EsimBotTest` | Отдельная БД `esim_bot_test` и отдельный пользователь `esim_bot_test_app`, SSL обязателен. Боевой connection string никогда не используется вместо тестового. |

Тестовый режим работает только через Polling; боевой webhook/URL игнорируется.
`Sales:Enabled`, курс Stars, условия продажи и аккаунт eSIM Access для него не нужны.
Существующий `Storage:EncryptionKey` оставьте без изменения.

Порядок проверки:

1. Войдите в [тестовую среду Telegram](https://core.telegram.org/bots/features#dedicated-test-environment)
   и создайте там нового бота через BotFather. В Telegram для macOS: десять нажатий
   на Settings открывают Debug Menu, затем ⌘ + Add Account. Для Telegram Desktop:
   Settings → Shift + Alt + правый клик по Add Account → Test Server.
2. Подготовьте отдельную тестовую БД командами ниже. Если она уже создана и строка
   подключения заполнена, повторное создание не требуется.
3. Заполните параметры теста, включите `PaymentTesting:Enabled` и перезапустите.
4. Отправьте `/testpayment` в личном чате тестового бота и оплатите помеченный TEST
   счёт. Сначала ожидается подтверждение платежа, затем запись в `/orders`.
5. Нажмите кнопку возврата или отправьте `/refund ID_ЗАКАЗА`. Возврат выполняется
   фоновым обработчиком через **тестовый** Telegram API; проверьте статус в `/orders`.
6. Повторите `/orders` после перезапуска: результат должен сохраниться. QR и профиль
   eSIM при этих проверках не создаются. Счета и возвраты доступны только указанному
   тестовому администратору.

```bash
# Из папки EsimBot; пароль MySQL администратора запрашивается скрыто.
dotnet run -- --setup-test-database 100.76.49.109
dotnet run -- --import-test-settings
dotnet run -- --check
```

Создание отказывается заменять существующую БД/учётную запись. Импорт добавляет
только тестовую строку подключения в `appsettings.json`; он не меняет боевые
доступы, ключ шифрования или переключатель режима. Новых таблиц в боевой БД нет;
в тестовой используются те же четыре таблицы. В `app_state` закреплено окружение:
приложение отклоняет запуск в чужой БД. Тестовые заказы дополнительно помечены
зарезервированным кодом, который закупочный клиент не принимает и в боевом режиме.

Для возврата к продажам выключите `PaymentTesting:Enabled` и перезапустите.
В подготовленной установке боевые доступы уже заполнены. Тестовая БД остаётся отдельно;
тестовые платежи не переносятся в боевые заказы. Простое создание другого бота
в обычном Telegram **не** делает платежи бесплатными.

Статус `/health/config` содержит `PaymentEnvironment`, `CanTestPayments` и
`CanSell` без секретов. В тестовом режиме `CanSell` всегда `false`.
Автоматические проверки не заменяют ручную оплату в тестовом Telegram; реальные
расходы поставщика и выдача eSIM проверяются отдельно в боевом режиме.

Токены, пароль MySQL и коды активации не выводятся в штатные журналы.
`appsettings.json` не попадает в Git и публичные HTTP-маршруты, но намеренно входит
в Build и любую публикацию. Папки и ZIP публикации содержат секреты: не выкладывайте
их в публичный репозиторий и не отправляйте посторонним. Для примера используется
`appsettings.Example.json`, исключённый из выходных папок. Старый Local сохранён
как резервная копия исходника, исключён из Git/публикации и больше не читается.
Специальный профиль **Server** включает этот файл в готовую папку для вашего сервера.
Эта папка содержит секреты: не публикуйте её открыто и ограничьте доступ учётной
записью приложения. При обычном `dotnet publish` без профиля конфиг копируется отдельно.

## Цена и доход

```text
закупкаUSD = ценаAPI / 10000
добавкаUSD = max(закупкаUSD × MarkupPercent / 100, MinimumProfitUsd)
базаUSDзаStar = 0.013 × 0.90 = 0.0117
коэффициентTelegram = 0.85 при включённых topics в личном чате; иначе 1
ценаStars = округлитьВверх((закупкаUSD + добавкаUSD) / (базаUSDзаStar × коэффициентTelegram))
```

База взята из [условий Telegram, раздел 6.2.4](https://telegram.org/tos/bot-developers#6-2-4-rewards-for-stars)
и проверена 04.10.2026; 10% вычитаются как расчётный резерв, не как утверждение о
фактических удержаниях. Публичный Bot API не сообщает личный чистый курс вывода.
Это встроенная оценка, а не автоматически обновляемый рыночный курс. При изменении
условий Telegram её следует обновить или переопределить `Sales:NetUsdPerStar`.

Флаг topics проверяется автоматически через `getMe` каждую минуту; его комиссия
15% учитывается отдельно. При отсутствии свежей проверки (старше двух минут)
новые продажи приостанавливаются, уже оплаченные заказы продолжают обрабатываться.
Если комиссия изменилась после выставления счёта, слишком дешёвый счёт отклоняется
при pre-checkout: покупатель выбирает тариф заново и видит актуальную цену.

Итоговая цена в Stars показывается до подтверждения оплаты. Заказ фиксирует цену
поставщика и цену покупателя; API получает проверку закупочной цены, поэтому
подорожавший пакет нельзя незаметно купить дороже за счёт сервиса.
В каталоге рядом показывается расчётный эквивалент в USD по закупочной цене и
наценке, например `107 ⭐ ≈ $1.25`. Это ориентир стоимости пакета, а не обещанная
цена покупки Stars: Telegram определяет её отдельно для страны и способа оплаты.
Расчётная разница не гарантирует прибыль после налогов, расходов на сервер,
изменения условий вывода Stars или возвратов. Telegram может удерживать поступившие
Stars до 21 дня; доступность вывода через Fragment зависит от аккаунта и страны.
Баланс eSIM Access пополняется отдельно: приложение не списывает деньги с вашей
карты и не переводит автоматически Stars поставщику.

## Работа бота

Поддерживаются азербайджанский, русский и английский. Начальный язык определяется
по Telegram; кнопка языка и `/language` сохраняют ручной выбор, который действует
после перезапуска и для уведомлений о выпуске/возврате. Выбор хранится в `app_state`,
новая таблица не создаётся. Поиск стран понимает названия на всех трёх языках и ISO-коды.
Названия и описания самих тарифов сохраняются в формулировке поставщика.

Меню: выбор/поиск страны → тарифы по возрастанию цены → условия и проверка телефона
→ счёт Telegram Stars → оплата → QR и ручные данные установки.
Покрытие берётся из действующего каталога API. Продаются фиксированные пакеты
трафика с известными условиями активации; дневные/FUP-тарифы не выдаются за обычные.
Реальные тарифы не заменяются демонстрационными, если ключ поставщика отсутствует.

`/orders` показывает только заказы пользователя, QR и данные расхода.
Статистика оператора может запаздывать. `/install`, `/support`, `/paysupport`,
`/terms` доступны из меню. `/id` показывает ваш Telegram ID.

Поддержка работает внутри бота: `/support` или `/paysupport` включает отправку
следующего текстового сообщения администратору. Пользователь видит предупреждение
и может отменить отправку через `/cancel`. Вы отвечаете обычной функцией **Reply**
на обращение, полученное от бота. Адресат определяется по сохранённому маршруту,
не по содержимому сообщения. Текст обращения в БД не сохраняется; временные
маршруты ответов удаляются после использования или истечения срока.
Для администратора та же кнопка открывает явно подписанную самопроверку:
отправленный вопрос приходит ему самому, и на него можно ответить через Reply.
Ответ на настоящее обращение покупателя имеет приоритет над самопроверкой.
Ссылки `https://t.me/RoamiSIMBot?start=support` и `?start=terms` открывают нужный
раздел напрямую. Неизвестные start-параметры по-прежнему открывают меню.

Администратор может использовать `/refund ID` для заказа, закупка которого ещё
не отправлена поставщику. `/retry ID` возвращает заказ из ручной проверки
к сверке с тем же исходным идентификатором. Если поставщик уже получил запрос,
неопределённый результат сначала сверяется; автоматического «слепого» возврата
в таком состоянии нет. Отзыв уже выпущенной eSIM выполняется через поддержку
поставщика после проверки состояния профиля.

Оплата записывается в MySQL **до** закупки. Повторные уведомления Telegram,
перезапуски и таймауты не создают новую закупку: используется неизменный
`transactionId`. Выдача и возвраты продолжаются из БД после перезапуска.
Код активации хранится с AES-256-GCM и привязкой к заказу. QR строится локально.

## База данных

База `esim_bot` содержит ровно четыре таблицы:

| Таблица | Данные |
| --- | --- |
| `orders` | Заказ, владелец, принятые условия, снимок цены, состояние обработки. |
| `payments` | Уникальный charge Telegram, фактический плательщик, Stars, состояние возврата. Неизменная отметка первичного платежа не позволяет перепутать его с лишним платежом. |
| `esims` | Один профиль на заказ, уникальный ID поставщика, ICCID, зашифрованный код, APN. |
| `app_state` | Ключ–значение: версия схемы, ID бота, позиция polling, языки и временные маршруты поддержки. |

Атомарные поля, FK, UNIQUE, CHECK и транзакции InnoDB обеспечивают целостность.
Тарифные справочники, страны и копии Telegram-профилей не хранятся.
Название/цена в заказе — исторические значения предложения, не копия живого каталога.
Стоимость поставщика всегда USD в целых единицах `1/10000`, цена клиента — целые Stars.
Все сессии MySQL и времена обработки используют UTC.

За каждой таблицей закреплён отдельный репозиторий. `OrderService` в BLL объединяет
вызовы нужных репозиториев одной транзакцией: разделение кода не разделяет атомарную
запись заказа/платежа/выданной eSIM. В контроллерах нет бизнес-логики: два оператора,
вызов интерфейса сервиса и возврат результата. У каждого контроллера ровно один
собственный BLL-сервис: `HealthController` → `IHealthService` / `HealthService`,
`TelegramWebhookController` → `ITelegramWebhookService` / `TelegramWebhookService`.
Это соответствие, одноимённость интерфейсов и двухстрочные действия контроллеров
проверяются архитектурными тестами.

Схема создаётся отдельно от штатного запуска. Сервис не получает права менять
таблицы. Команда `--setup-database HOST` предназначена только для новой пустой
установки и отказывается заменять существующую БД/учётную запись. Для текущего
сервера создание уже выполнено; повторять его не нужно.

## Проверки и публикация

`EsimBot.csproj` использует `Microsoft.NET.Sdk.Web`: это ASP.NET Core Web API/MVC,
а не desktop-приложение. В `Properties/launchSettings.json` есть веб-профили
**EsimBot Web (HTTP)** и **EsimBot Web (HTTPS)**; в IDE они открывают `/home/index`.
На Windows также доступен IIS Express. Профили разработки не переносятся на сервер.
Если Rider уже открыт со старой конфигурацией, перезагрузите проект и выберите
**EsimBot Web (HTTP)** в `.NET Launch Settings Profile`
([документация Rider](https://www.jetbrains.com/help/rider/Running_LaunchSettings.html)).
Не запускайте второй экземпляр с боевым ботом одновременно с работающим сервером.
`UseAppHost=false` даёт переносимую `EsimBot.dll`, а публикация для IIS содержит
`web.config` с ASP.NET Core Module. На Linux приложение работает через Kestrel.

Для публикации из IDE выберите проект **EsimBot**. Можно использовать любой
профиль или обычный Publish: заполненный `appsettings.json` всегда копируется.
Готовый профиль **Server** лишь задаёт папку публикации и IIS Production.
Результат — `artifacts/esim-bot-server/`: перенесите **всю папку публикации**, а не
исходники. В неё уже включён ваш заполненный `appsettings.json`. Для боевого запуска
оставьте `PaymentTesting:Enabled=false`; боевые доступы уже заполнены.
Та же публикация из терминала:

```bash
dotnet publish EsimBot/EsimBot.csproj -c Release /p:PublishProfile=Server
```

Из корня solution:

```bash
dotnet build EsimBot/EsimBot.csproj -c Release
dotnet test EsimBot.Tests/EsimBot.Tests.csproj
dotnet run --project EsimBot/EsimBot.csproj -- --check-config
dotnet run --project EsimBot/EsimBot.csproj -- --check
dotnet run --project EsimBot/EsimBot.csproj -- --verify-db
dotnet run --project EsimBot/EsimBot.csproj -- --check-provider
dotnet run --project EsimBot/EsimBot.csproj -- --check-stats
dotnet publish EsimBot/EsimBot.csproj -c Release -o artifacts/esim-bot-publish /p:UseAppHost=false
```

`--check-config` проверяет только заполненность настроек, без БД, Telegram или
поставщика. Выводит только флаги, не пароли и токены. Его можно запускать прямо
в папке публикации: `dotnet EsimBot.dll --check-config`.
`--check` проверяет настройки и доступность схемы, не запускает Telegram и не
покупает eSIM. Ненулевой код до заполнения всех параметров ожидаем.
`--verify-db` проверяет реальную БД тестовой транзакцией с полным откатом.
`--check-provider` читает баланс и каталог eSIM Access, не покупая eSIM; в тестовом
режиме поставщик заблокирован. Если заполнен SecretKey, проверка использует
подписанные HMAC-запросы. Webhook поставщика регистрировать не требуется: выдача
сверяется фоновыми запросами по номеру заказа.
`--check-stats` выполняет тот же агрегированный read-only запрос, что кнопка
администратора, без отправки сообщения и без изменения данных.
Опциональные интеграционные тесты включаются переменной `ESIMBOT_INTEGRATION_CONFIG`,
содержащей полный путь к подготовленному конфигурационному файлу. Они создают
свои уникальные тестовые строки, затем удаляют только их и проверяют очистку.
Ни эти тесты, ни диагностика не обращаются за покупками к поставщику/Telegram.

На сервере установите ASP.NET Core Runtime 8; для IIS — соответствующий Hosting Bundle.
Перенесите содержимое публикации. При обычной публикации и с профилем Server
все настройки уже находятся внутри `appsettings.json`; ничего переносить отдельно
не нужно. Старый `appsettings.Local.json` на сервере игнорируется.
Для Linux/обычного запуска:

```bash
dotnet EsimBot.dll
```

Публикация содержит `web.config` для IIS. Приложение должно постоянно работать,
чтобы обрабатывать выдачу и возвраты: в IIS включите AlwaysRunning, Preload Enabled
и отключите idle timeout. Для Polling публичный webhook не нужен. Для Webhook
настройте HTTPS-домен/прокси и укажите полный адрес в конфигурации. С сервером
`100.76.49.109:3306` должен быть сетевой доступ (это приватный адрес).

Один активный экземпляр обслуживает одну БД и одного Telegram-бота. MySQL lock
предотвращает параллельную обработку двумя экземплярами. Не включайте web garden
или несколько активных реплик без отдельной доработки координации.

HTTP-маршруты:

- `GET /`, `/home/index`, `/ru` — русский лендинг; `/az` и `/en` — переводы;
- `GET /robots.txt`, `/sitemap.xml` — правила обхода и карта трёх канонических страниц;
- `GET /health/live` — процесс работает;
- `GET /health/config` — только признаки заполненности, без секретных значений;
- `GET /health/ready` — `200`, когда бот запущен и готов обрабатывать события; иначе `503`.
  Отключение новых продаж не прерывает обработку уже оплаченных заказов и возвратов;
- `POST /api/telegram/webhook` — только в режиме Webhook и с правильным
  `X-Telegram-Bot-Api-Secret-Token`; платежи подтверждаются после сохранения.

## Лендинг, нагрузка и баланс

Лендинг рендерится Razor на сервере, без внешних шрифтов, запросов к поставщику
или БД. Единственный небольшой JavaScript обрабатывает нажатие мобильной ссылки:
сначала открывает официальный `tg://resolve` именно для `RoamiSIMBot`, а при
неудаче оставляет HTTPS-переход `t.me` с тем же `start`-параметром. Контент,
навигация и FAQ работают без JavaScript. Публичный адрес в SEO-разметке —
`https://esimbot.digify.az/`; при переезде меняйте его в `HomeService` и шаблоне.
Реализованы отдельные языковые URL, title/description, canonical/hreflang,
Open Graph/Twitter и JSON-LD Organization/WebSite/WebPage. `/home/index` и `/ru`
ссылаются canonical на `/`; в sitemap только канонические URL. Ответы лендинга
кэшируются на 5 минут, статические ресурсы — на сутки.
Это техническая SEO-подготовка, не обещание места в поиске. После публикации
добавьте sitemap в Google Search Console вашего домена. Рекомендации:
[локализованные страницы](https://developers.google.com/search/docs/specialty/international/localized-versions),
[канонические URL](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls).

Ограничения нагрузки встроены, дополнительных настроек не требуется:

- 12 обработчиков обычных команд, не более 256 задач всего и 4 на чат;
  порядок внутри чата сохраняется. Перегрузка не создаёт бесконечную очередь;
- pre-checkout и финансовые события имеют независимые группы по 8 слотов;
  оплаты разных покупателей обрабатываются параллельно, одного — по порядку;
- polling фиксирует позицию после сохранения всей финансовой части пакета;
  webhook при перегрузке/ошибке сохранения возвращает 503 для повтора Telegram;
- общий каталог обновляется раз в 2 минуты одним запросом даже при одновременном
  наплыве покупателей. Ожидание покупателя ограничено 8 секундами;
- у поставщика максимум 4 запроса одновременно, 32 допущенных, ожидание в очереди
  до 2 секунд. Покупка не повторяется HTTP-клиентом вслепую;
- выдача ограничена 3 параллельными заказами. Возвраты выполняются отдельным циклом,
  чтобы медленный поставщик не блокировал их;
- отправка сообщений Telegram ограничена 25 запросами в секунду, не чаще одного
  запроса в секунду на чат, с ограниченной очередью. Ответы pre-checkout, callback,
  получение обновлений и запросы возврата не ждут эту очередь. Скрытые повторы
  запросов Telegram SDK отключены, повтором финансовых операций управляет БД;
- языковые настройки кэшируются на 2 минуты с лимитом 5000 записей; ручной выбор
  сразу обновляет кэш. Уже сохранённые финансовые события не откатываются из-за
  неудачного информационного сообщения в Telegram.

Очередь обычного интерфейса находится в памяти: после перезапуска пользователь
может повторить команду. Оплаты, заказы и возвраты остаются в БД. Один экземпляр
бота всё ещё обязателен; это не распределённая очередь и не защита от сетевого DDoS.
Реальная скорость также ограничена [лимитами Telegram](https://core.telegram.org/bots/faq#my-bot-is-hitting-limits-how-do-i-avoid-this),
API поставщика и ресурсами сервера.

Баланс поставщика проверяется каждые 5 минут и перед оплатой/началом закупки.
Если средств недостаточно, администратор получает личное сообщение: остаток,
стоимость требуемого пакета и сколько нужно добавить, в USD. При периодической
проверке без заказа ориентир — самый дешёвый доступный пакет. При всплеске
сохраняется одно уведомление с наибольшей нехваткой для одного пакета, не сумма
всех корзин. Перед отправкой остаток перечитывается; неизменившееся предупреждение
повторно не отправляется, изменившееся — не чаще раза в 5 минут.
История предупреждения хранится в существующей `app_state`; новых таблиц нет.
После пополнения оплаченные, ещё не отправленные поставщику заказы продолжаются
автоматически. Уже начатые закупки сверяются независимо от остатка баланса.
В тестовом режиме монитор не запускается. Администратор должен открыть бота
и нажать Start, иначе Telegram не разрешит личные уведомления.

## Граница готовности

В проекте реализован клиент реального production API eSIM Access. Выбор основан
на отсутствии минимального количества заказов и наличии документированной
идемпотентности; это не подтверждение минимальной цены во всех странах.
Для сравнения цен нужны актуальные тарифы партнёрских аккаунтов.
Аккаунт поставщика, его баланс, Telegram-бот и коммерческие условия заполняются владельцем.
Без этих данных реальная закупка, оплата и активация не считаются проверенными.

Источники: [eSIM Access API](https://docs.esimaccess.com/),
[условия без MOQ](https://esimaccess.com/docs/do-i-need-to-sign-a-contract-and-a-moq-to-kickoff/),
[оплата цифровых услуг в Telegram Stars](https://core.telegram.org/bots/payments-stars),
[размещение ASP.NET Core в IIS](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/iis/).
